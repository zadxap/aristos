# Миграция Aristos на Tauri 2: десктоп + Android APK, напоминания и виджеты

## Контекст
Aristos — офлайн-PWA (Vite + React 19 + TS), данные в IndexedDB, синк Canvas/Platonus через расширение + cloud-worker на Vercel/CF. Цель: нативные напоминания и домашние виджеты на Android, нативные уведомления на десктопе — то, чего не даёт PWA. Решение: Tauri 2 как обёртка над тем же vite-билдом. Матрица (согласована): Android — sideload APK; Windows/Linux — CI; macOS — CI, dmg без аккаунта (Gatekeeper: правый клик → Открыть); **iOS — нативно не делаем**, остаётся существующая PWA. Виджеты — свой Kotlin (RemoteViews), community-плагин `tauri-plugin-widgets` (0.x, 27 звёзд, 1 мейнтейнер) — задокументированный план Б. Push/FCM и iOS-виджеты — вне скоупа.

Веб-версия не меняется: расширение, userscript, curriculum-builder, vercel.json — не трогаем.

## Ключевые факты из кодовой базы (найдено исследованием)
- SW регистрируется инжектом vite-plugin-pwa в `index.html` (ручного кода нет) — в Tauri фейлится молча, менять нечего. Boot-error hook не конфликтует.
- `src/App.tsx` — **BrowserRouter**: под `http://tauri.localhost` путь-роутинг ненадёжен → при `isTauri()` используем `HashRouter`, на вебе оставляем BrowserRouter.
- Уведомления v0 уже есть: `src/lib/notifications.ts` (настройки `NotifSettings` в localStorage `aristos-notif-settings-v1`, dedupe `notifyOncePerDay`) + `src/components/layout/NotificationAgent.tsx` (тик раз в минуту, логика отбора пар/дедлайнов, работает только при видимой вкладке). Переиспользуем логику отбора, меняем транспорт.
- Для виджетов есть готовые чистые функции: `getCurrentStatus()` в `src/lib/status.ts` (ближайшая пара, праздники, семестр), `getAcademicWeek()` в `src/lib/academic-week.ts`, фильтр дедлайнов в `UpcomingDeadlines.tsx:21-26`. Данные: `schedules` (`ScheduleEntry{day:'mon'..'sun', start:"HH:MM", subject_name, room}`), `canvasAssignments` (`due_at` ISO, `submitted_at`, `graded`), `calendars` (`midterm_controls/holidays` — строки "YYYY-MM-DD").
- `src/lib/cloud.ts` ходит на `https://aristos-sync.aristoss.workers.dev` обычным fetch — нужен только CORS: воркер (`sync-worker/wrangler.toml`, ALLOWED_ORIGIN — comma-list) + `http://tauri.localhost`, `tauri://localhost`. AI (OpenAI/Gemini) CORS-friendly, работает как есть.
- PDF (`UploadedPdfs.tsx:58` открывает blob через window.open) в Android WebView не работает — WebView не рендерит PDF. Нужен встроенный просмотрщик (pdf.js), иначе uploaded PDF мертвы в APK.
- Настройки UI: SideMenu-модалка (`src/components/layout/SideMenu.tsx`), паттерн — нативные checkbox + `Modal` из `components/ui/modal.tsx`. i18n — свой proxy (`src/i18n/kk.ts` base + `ru.ts`, TS-паритет ключей).

## Этап 0 — окружение (локально, один раз)
`sudo pacman -S --needed rustup webkit2gtk-4.1 base-devel` → `rustup default stable` → `npm i -D @tauri-apps/cli @tauri-apps/api`. Если локальная сборка окажется тяжёлой — все нативные сборки уходят в CI (этап 4), локально только правки.

## Этап 1 — каркас Tauri (desktop)
- `npx tauri init`: `src-tauri/` с `tauri.conf.json` — identifier `kz.yessenov.aristos`, `frontendDist: "../dist"`, `beforeBuildCommand: "npm run build"`, `beforeDevCommand: "npm run dev"`, `devUrl: "http://localhost:5173"`. В `src-tauri/Cargo.toml` — `tauri = "2"`. Иконки: `npx tauri icon` от `public/icons/icon-512.png`.
- `src/lib/tauri.ts`: `export const isTauri = () => "__TAURI_INTERNALS__" in window`.
- `src/App.tsx`: `<isTauri() ? HashRouter : BrowserRouter>` (все 8 маршрутов без изменений).
- **PDF-просмотрщик**: маршрут `#/pdf/:id` + `src/pages/PdfViewerPage.tsx` на `pdfjs-dist` (blob из `pdf-store.ts`); в `UploadedPdfs.tsx` при `isTauri()` — переход на этот маршрут вместо window.open (на вебе оставить как есть). Бонусом работает и в PWA.
- Desktop-сборка: `npx tauri build` (deb/AppImage на Linux), `npx tauri dev` для отладки.

## Этап 2 — нативные напоминания (все платформы)
- Rust: `tauri-plugin-notification = "2"` + JS `@tauri-apps/plugin-notification`. Разрешения capabilities в `src-tauri/capabilities/`.
- Новая `src/lib/reminders.ts`: при старте приложения / после синков / при изменении настроек собирает окно ближайших ~24–48 ч (переиспользуя фильтры `NotificationAgent.tsx`: пара за `minutesBefore`, дедлайны ≤48 ч, учёт семестра/праздников) и вызывает Rust-команду `schedule_reminders(events_json)`.
- Rust-команда `schedule_reminders` (в `src-tauri/src/lib.rs`): отменяет прошлые scheduled-уведомления, ставит новые через scheduling API плагина; Android-каналы «Уроки»/«Дедлайны». Если scheduling API плагина окажется недостаточным — fallback: AlarmManager внутри мини-плагина этапа 3.
- `NotificationAgent.tsx` при `isTauri()`: показ через `@tauri-apps/plugin-notification` (perm: `isPermissionGranted/requestPermission`), dedupe-журнал остаётся.
- AndroidManifest (gen/android): `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`, `VIBRATE`. **ProGuard minify не включать** (известно ломает notification-плагин).
- Settings UI: секция уведомлений в `SideMenu.tsx` — переключатели «Напоминать о парах/дедлайнах», выбор `minutesBefore` (5/10/15/30). Новые i18n-ключи в `kk.ts` + `ru.ts`.

## Этап 3 — виджеты Android (Kotlin, RemoteViews)
- `npx tauri android init` (нужен Android SDK; если локально нет — сгенерировать через CI once и закоммитить `src-tauri/gen/android`).
- Мини-плагин (Kotlin ~100 строк в gen/android + Rust-стаб): команда `widget_update(json)` — сохраняет снапшот в SharedPreferences и форсит `AppWidgetManager`-refresh всех виджетов.
- `src/lib/widget-snapshot.ts`: компактный снапшот `{lang, activeCourse, activeSemester, today: [{time, name, room, type}], week: [{day, entries}], deadlines: [{title, due, badge}], generatedAt}` — строки **заранее локализуются/форматируются в JS** (через `kk.*` и `getCurrentStatus`), виджет — тупой рендерер строк. Пуш при каждом открытии приложения, после синков и при смене активного курса/семестра.
- 3 провайдера: `NextPairsWidget` (4×2 — следующая пара + 2 последующих), `WeekScheduleWidget` (4×4, resizable 5×4 — грид дней), `DeadlinesWidget` (4×2/4×3 — список до 5 дедлайнов с бейджем типа). XML-layouts + `<widget-info>` + receivers в AndroidManifest. Тап — просто открытие приложения (deep-link на секции — опционально позже).
- Периодическое самобновление провайдера (updatePeriodMillis + чтение SharedPreferences) на случай убитого процесса приложения.

## Этап 4 — CI (.github/workflows/release.yml)
Триггеры: `workflow_dispatch` + теги `v*`.
- **ubuntu** + `tauri-apps/tauri-action@v0`: Linux deb/AppImage.
- **windows**: NSIS-инсталлер (tauri-action).
- **macos-14**: dmg (tauri-action, ad-hoc подпись — в описании релиза инструкция про Gatekeeper).
- **ubuntu + Android**: JDK 17, Android SDK/NDK setup, `npx tauri android build --apk --target aarch64 --target armv7`; подпись релизным keystore из секретов (`ARISTOS_KEYSTORE_BASE64`, пароль — секреты). **Keystore сгенерировать один раз и хранить** — иначе APK-обновления не встанут поверх старых.
- Артефакты — в GitHub Release (tauri-action создаёт release по тегу).

## Этап 5 — CORS воркера + документация
- `sync-worker/wrangler.toml`: добавить `http://tauri.localhost,tauri://localhost` в ALLOWED_ORIGIN. **Действие юзера**: `cd sync-worker && npx wrangler deploy`.
- Обновить CONTEXT.md (архитектура, команды, известные ограничения: Android WebView не рендерит PDF — теперь pdf.js; iOS = PWA).

## Проверка
1. `npm run typecheck && npm run lint && npm run build` — фронт зелёный.
2. Desktop локально: `npx tauri dev` — данные грузятся, cloud pull работает (после деплоя воркера), тест-напоминание всплывает, PDF открывается в pdf.js, роутинг по всем 7 разделам не ломается.
3. Веб-регрессия: `npx vite preview --port 5174 --strictPort` — поведение прежнее, SW/обновления работают как до миграции.
4. Android (через CI артефакт): APK ставится, вход в приложение, pull из облака, добавление всех 3 виджетов на домашний экран, снапшот заполняется после первого открытия, напоминание срабатывает при убитом приложении.
5. Чистое состояние: новый профиль/данные отсутствуют — приложение не падает (BOOT ERROR hook).

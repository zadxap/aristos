# Нативный синк Canvas + Платонус в desktop-приложении (замена расширения)

## Контекст
Сейчас Canvas/Платонус-данные добываются только браузерным расширением (живая сессия + hidden-tab harvest) и докидываются в PWA через localStorage/postMessage. В Tauri-приложении у WebView свой cookie-jar, а скрытые окна могут загружать внешние сайты и исполнять JS — значит **тот же механизм переносится внутрь приложения**: пользователь один раз логинится в окне приложения, дальше синк запускается кнопкой в настройках. Телефон продолжает получать данные через облако (уже работает). Расширение остаётся для чисто-браузерных пользователей PWA; нативный UI скрыт на вебе и Android (`isTauri() && !isTauriMobile()`).

Ключевой факт из исследования: userscript **уже доказывает**, что весь Canvas-синк работает как same-origin JS внутри страницы Canvas (`window.ENV.csrfToken` + `fetch('/api/v1/...')` + Link-пагинация). Платонус требует живого DOM (данные журнала приходят XHR-ом самого сайта; оценки по дням — только по клику на карточку → `#marksModal`). Значит перенос = инжект существующих скриптов в скрытые webview + возврат данных через IPC.

## Архитектура

```
[main window UI] --invoke--> [Rust: sync_open/sync_eval/sync_close/sync_url]
      |                            |
      | event 'sync-payload'       v
      +<---invoke('sync_payload')--[hidden webview 'harvest' на canvas/platonus]
                                        (инжект-скрипты = порты userscript + platonus-inpage)
```

- **Rust (`src-tauri/src/sync.rs`)**: `sync_open(url, visible)` — создать/переиспользовать окно label `harvest` (`WebviewWindowBuilder::new(..., WebviewUrl::External(url))`, при `visible=false` скрытое; при смене URL — `navigate()` или пересоздание), `sync_eval(js)` — `window.eval(...)`, `sync_url()` — текущий URL (детект конца логина), `sync_close()`, `sync_payload(json)` — команда, которую вызывает инжект-скрипт из внешней страницы: шлёт `app.emit("sync-payload", json)` в main window. Регистрация в `lib.rs`.
- **Права**: `src-tauri/permissions/aristos.toml` — добавить permission'ы для 5 команд; `capabilities/default.json` — их для main; **новый** `capabilities/remote-sync.json` — `"windows": ["harvest"], "remote": {"urls": ["https://canvas.yu.edu.kz/*", "https://platonus.yu.edu.kz/*", "https://id.yu.edu.kz/*"]}, permissions: ["allow-sync-payload"]` (подтверждено docs: remote-контекст в capabilities даёт IPC внешним страницам).
- **`tauri.conf.json`**: `"app": {"withGlobalTauri": true}` — инжект-скрипты на внешних страницах получают `window.__TAURI__.core.invoke`.
- **Инжект-скрипты** (vite `?raw`-импорты, текст инжектится через `sync_eval`):
  - `src/lib/injected/canvas-collector.js` — порт сборщика из `userscript/aristos-sync.user.js` (same-origin fetch `/api/v1/users/self` (проверка сессии) → `/courses` → `/users/self/enrollments` → на каждый курс `/courses/{id}/assignments?include[]=submission&per_page=100`, Link-пагинация ≤50 страниц, нормализация `itemType/extractCode`, payload `{format:'aristos-canvas-sync', version:1, source:'app', ...}`) с заменой доставки: `window.__TAURI__.core.invoke('sync_payload', {json})` вместо postMessage.
  - `src/lib/injected/platonus-page.js` — порт `extension/platonus-inpage.js` (парсер карточек `.card[data-id]`, клик-harvest `#marksModal`, probe/extract) + драйвер: `discover` (studentID из `window.student`, годы/семестры из selects) и `harvest(year, term, withMarks)` — page-side `setTimeout`-поллинг «Ср.тек» (десктоп-WebView не троттлится как Chrome SW) → payload'ы через `sync_payload` по стадиям.
- **JS-оркестрация `src/lib/native-sync.ts`**: дергает команды, слушает `event.listen('sync-payload')`, валидирует payload'ы **существующими** `isCanvasSyncPayload`/`isPlatonusSyncPayload`, применяет через **существующие** `useDB().syncCanvas/syncPlatonus` (React-стейт, авто-маппинг курсов, авто-push в облако — всё бесплатно). Прогресс-события — в React-стейт UI. `platonusStudentID` + выбранные периоды — в settings store (`getSetting/saveSetting`).
- **Логин**: при 401 (`payload.reason === 'need-login'`) — `sync_open(loginUrl, visible=true)`: Canvas → `https://canvas.yu.edu.kz/login/canvas`, Платонус → `https://platonus.yu.edu.kz/` (SSO через id.yu.edu.kz); JS поллит `sync_url()` раз в секунду, пока не уйдёт со страницы логина → закрыть → ретрай синка.
- **UI в `SideMenu.tsx`** (секция «Синхронизация», только desktop): Canvas — статус последнего синка (`canvasLastSync`) + [Войти]/[Синхронизировать]; Платонус — [Найти периоды], чекбоксы `{year}-{term}` (все выбраны по умолчанию), [Импорт выбранных], строка прогресса. Тосты — паттерн `CanvasSyncListener` (ключи `syncCanvasOk/Fail*` уже есть; новый `source: 'app'` добавить в union в `src/types/index.ts:140`). Часть пост-модалок/лейблов — новые i18n-ключи kk/ru.

## Не трогаем
`extension/`, `userscript/`, `CanvasSyncListener` (живёт для браузерных юзеров), cloud-протокол, `applyCanvasSync`-семантику (полный снапшот — как в расширении).

## Верификация
1. `npm run typecheck && npm run build` + `npx tauri build` — билд зелёный (ACL-пермишены проверяются на этапе tauri-build).
2. Desktop smoke: бинарник запускается, секция синка видна.
3. **Живой тест (юзер)**: «Синхронизировать Canvas» с живой сессией → payload применён, тост с количеством, DeadlinesPage показывает свежий `canvasLastSync`; с истекшей сессией → окно логина → после входа автопродолжение. Платонус: «Найти периоды» → список лет/семестров → «Импорт выбранных» → прогресс по карточкам → оценки по дням открываются в UI.
4. Облако: после синка авто-push (телефон получает данные pull'ом).
5. Веб-регрессия: в браузере секция синка отсутствует, расширение продолжает работать.

## Риски /_known unknowns
- `withGlobalTauri` на remote-страницах и `navigate()` vs пересоздание окна — два места, где может понадобиться CI-итерация (симптомы: `__TAURI__ is undefined` / окно не грузит новый URL) — лечится конфигом/пересозданием.
- Платонус-маршрут SSO (id.yu.edu.kz) может требовать двойного захода (docs) — поллинг `sync_url()` это покрывает.
- iOS не входит (нет iOS-цели). Мобильный Tauri — sync UI скрыт.

## 1. Архитектура: это ДВА приложения, а не одно

✅ На домене `platonus.yu.edu.kz` живут два независимых фронтенда:

| Приложение | Расположение | Технологии | Роутинг |
|---|---|---|---|
| «Студенческий журнал» и служебные страницы | корень домена (`/student_register`, `/calendarview`, `/indcur`, …) | v6-шаблон (`/template.html`), AngularJS + jQuery | обычные URL-пути, серверный рендер |
| «v7» — современный SPA | `/v7/` | SPA | **hash-роуты** (`/v7/#/schedule/studentView` и т.п.) |

✅ Страницы `/student_register` и подобные живут **вне** `/v7/` — это отдельное приложение на v6-шаблоне.
✅ Сессия общая: cookies на домене `platonus.yu.edu.kz`.

**Практический вывод для Aristos:** журнал оценок (главный источник истории) — это обычный сервер-рендерный GET, не SPA-API. Парсить его надо DOMParser'ом, а не ждать JSON.

## 2. Вход / аутентификация (SSO)

✅ Прямой логин на `platonus.yu.edu.kz` не используется — вход идёт через SSO-сервер `id.yu.edu.kz`.

Полная цепочка:

1. Открыть `https://id.yu.edu.kz/platonus/oauth`
   (если SSO-сессии ещё нет — покажется форма логин/пароль на `id.yu.edu.kz`).
2. После ввода логина/пароля **повторно открыть** `https://id.yu.edu.kz/platonus/oauth`
   → произойдёт редирект на `https://platonus.yu.edu.kz/v7/#/main-event/view`.
3. Сессия установлена: cookies выставлены на домен `platonus.yu.edu.kz`.

✅ Все дальнейшие запросы (и к v7 REST, и к сервер-рендерным страницам) идут с этими cookies.
✅ Для fetch из расширения/скрипта: `credentials: 'include'`.

❓ Открытые вопросы:
- Время жизни сессии (когда именно истекает) не измерено.
- Поведение refresh-механики v7 при истечении сессии не изучено (см. чеклист в конце).

Пример проверки сессии из консоли/скрипта:

```js
await fetch('https://platonus.yu.edu.kz/student_register?studentID=208&year=2026&term=1', {
  credentials: 'include'
}).then(r => r.status);
// 200 + HTML → сессия жива; редирект на логин → сессия истекла
```

## 3. Токен v7 (localStorage)

✅ После входа в `localStorage` домена `platonus.yu.edu.kz` есть ключ **`token`** — UUID. Его использует v7 SPA для вызовов `/rest/api/...`.

✅ Также в `localStorage` присутствуют: `fio`, `isStudent`, `roleID`.

❌ **`studentID` в localStorage НЕТ** — его надо брать из страницы журнала (см. §4) или другого источника.

❓ Открытый вопрос: точный формат авторизации v7 REST — **предположительно** `Authorization: Bearer <token>`, но это **точно НЕ проверено**. Проверить при работе: перехватить заголовки любого XHR-запроса v7 в DevTools → Network.

## 4. Журнал оценок — главный источник данных (сервер-рендер)

### 4.1 URL и формат ответа

✅ Журнал отдаётся обычным GET с куками:

```
GET https://platonus.yu.edu.kz/student_register?studentID={id}&year={Y}&term={T}
```

Пример:

```
https://platonus.yu.edu.kz/student_register?studentID=208&year=2026&term=1
```

✅ Ответ — **полностью готовый HTML** (~84 КБ), никакой дополнительной загрузки данных по XHR не требуется. Всё содержимое (карточки предметов, таблицы оценок) уже в разметке.

### 4.2 studentID

✅ `studentID` берётся из самой страницы журнала — там объявлена глобальная переменная:

```js
window.student = { studentID: 208 };
```

То есть: открыть `/student_register` без параметров (или с любыми), прочитать `window.student.studentID`, дальше строить URL с нужными годом/периодом.

### 4.3 Параметры year / term

✅ Селекты года и периода на странице — обычная HTML-форма:

```html
onchange="form.submit()"
```

✅ Отправляется GET с полями `studentID`, `year`, `term`.
✅ Значения `term`:

| term | Период |
|---|---|
| `1` | 1-й (осенний) семестр |
| `2` | 2-й (весенний) семестр |
| `-1` | дополнительный период 1 |
| `-2` | дополнительный период 2 |

❓ Открытые вопросы: поведение доп. периодов `-1` / `-2` (что именно в них попадает — пересдачи, летняя сессия?) не изучено.

### 4.4 Что содержится в HTML

✅ **Карточки предметов** (верхний уровень страницы). Проверенная разметка карточки
(живой HTML, дамп `tools/platonus-dump-sample.html`):

```html
<div class="row">
  <div class="col-md-4" ng-repeat="subject in subjects" journal-repeat-directive>
    <div class="main-box clearfix project-box green-box">
      <div class="card border" data-id="63">                     <!-- subjectID -->
        <div class="project-box-header" ng-click="getMarks(subject.subjectID, …)"
             data-bs-toggle="modal" data-bs-target="#marksModal">
          <div class="name" title="Иностранный язык 1(IYa 111152-14-P)">
            <a>Иностранный язык 1(IYa 111152-14-P)</a>  <!-- текст ОБРЕЗАЕТСЯ «...» -->
          </div>
        </div>
        <div align="center">Сапарова А.И</div>                   <!-- преподаватель -->
        <div class="project-box-content">
          <span class="chart" data-percent="92.0">               <!-- донут: ЗДЕСЬ %, -->
            <span class="percent">0</span>%                      <!-- а тут всегда 0 -->
          </span>
        </div>
        <div class="project-box-footer clearfix">
          <a ng-repeat="exam in subject.exams">
            <span class="value">87.00</span><span class="label">Ср.тек. 1</span>
          </a>  <!-- пары value/label: Ср.тек. 1, Ср.тек. 2, РК 1, РК 2, Рейтинг, Экз.; -->
        </div>   <!-- прочерк «-» = null; бывает метка «ДЗ» (физкультура) -->
      </div>
    </div>
  </div>
</div>
```

Важные факты:
- **Текст ссылки Платонус обрезает** длинные названия («Информационно-коммуникационные
  технологи ...») — ПОЛНОЕ «Название(Код)» живёт только в `title` атрибуте. Парсер v2
  на regex по тексту из-за этого терял предметы и путал код.
- **Донут**: реальный % — в `data-percent` у `.chart`; видимый `span.percent` всегда 0
  (его анимирует JS). У неоцененного предмета `data-percent="0"`.
- Есть вложенная обёртка `div.card.mb-4` вокруг ряда карточек — у неё нет `data-id`,
  её надо отфильтровывать.
- Значения берутся парами `.value`/`.label` из `.project-box-footer` — структурно, без regex.

✅ **Оценки по дням — НЕ в исходном HTML.** `#marksModal` пуст (`ngRepeat: classType in
marks`), таблицы появляются ТОЛЬКО после клика на карточку: `getMarks(subjectID, …)`
делает XHR и заполняет модалку. В модалке на каждый вид занятий — секция
«КОД (Преподаватель)» + таблица Месяц (colspan-ячейки) / Дата / Оценка. Суффиксы кода:

| Суффикс кода | Вид занятий |
|---|---|
| `-L` | лекции (например `NOOKTO 113142-1-L`) |
| `-P` / `-Р` (кириллическая!) | практика |
| `-SRSP` | БӨЖ (СРСП) |

Учебный год: месяцы 9–12 = year, 1–8 = year+1 (осень/весна/лето академического года).

⚠️ Скрытая вкладка: таймеры страницы Chrome троттлит (до минуты после 5 минут в фоне),
поэтому ожидания (поллинг `#marksModal`) делает background-воркер executeScript-ами,
а не setTimeout внутри страницы.

### 4.5 Как парсить

✅ Парсить `DOMParser`'ом по структуре таблиц:

```js
const html = await (await fetch(url, { credentials: 'include' })).text();
const doc = new DOMParser().parseFromString(html, 'text/html');
const studentID = doc.defaultView === null
  ? Number(html.match(/window\.student\s*=\s*\{[^}]*studentID:\s*(\d+)/)?.[1])
  : undefined;
// далее: найти карточки предметов, для каждой — блоки таблиц по кодам дисциплин
```

❓ Открытый вопрос: точные CSS-селекторы карточек/модалок не зафиксированы в этой документации — при реализации сверяться с реальной разметкой ответа (структура стабильна, но классы могут быть автогенерированными).

### 4.6 Статус

✅ Это **основной путь импорта истории оценок** в Aristos.

## 5. Формула итоговой оценки (подтверждена числами журнала)

✅ Семестровые показатели считаются так:

```
РК1     = Ср.тек.1        (среднее текущих оценок до 1-й рубежки)
РК2     = Ср.тек.2        (среднее текущих оценок до 2-й рубежки)
Рейтинг = (РК1 + РК2) / 2
Итог    = round(0.6 × Рейтинг + 0.4 × Экз)
```

✅ Контрольные примеры из живого журнала:

| Предмет | Расчёт | Результат |
|---|---|---|
| Философия | (74.53 + 69.69) / 2 = 72.10 → 0.6×72.10 + 0.4×100 = 83.26 | донут **83.00** |
| Социология | по той же формуле | **80** |
| Психология | по той же формуле | **85** |

✅ Формулу можно использовать в Aristos для предсказания итога по текущим оценкам (что будет, если экзамен написан на X).

## 9. План интеграции в Aristos (предложение)

Общая схема: **тот же MV3-extension**, что уже используется для Aristos, получает доступ к Платонусу и перекачивает журнал в PWA.

### 9.1 Шаги

1. **Manifest V3:** добавить `host_permissions` на `https://platonus.yu.edu.kz/*` (и при необходимости `https://id.yu.edu.kz/*` для обнаружения состояния логина).
2. **Кнопка в попапе:** «Платонус: журнал».
3. **Загрузка данных** (content-script или background fetch):
   ```
   GET /student_register?studentID=...&year=Y&term=T
   ```
   для нужных лет/семестров (studentID — из `window.student`, см. §4.2).
4. **Парсинг:** `DOMParser` → извлечь карточки (итоги) и таблицы (оценки по дням) — см. §4.4–4.5.
5. **Payload** — формат:

```json
{
  "format": "aristos-platonus-sync",
  "version": 1,
  "years": [
    {
      "year": 2026,
      "term": 1,
      "subjects": [
        {
          "name": "Философия",
          "code": "FIL 2102",
          "teacher": "...",
          "final": 83.0,
          "srTek1": 74.53,
          "rk1": 74.53,
          "srTek2": 69.69,
          "rk2": 69.69,
          "rating": 72.10,
          "exam": 100,
          "marks": [
            {
              "code": "FIL 2102-38-L",
              "kind": "lecture",
              "date": "2026-09-15",
              "mark": 5
            }
          ]
        }
      ]
    }
  ]
}
```

   `kind` ∈ `'lecture' | 'practice' | 'srsp'` (определяется по суффиксу кода: `-L`, `-P`, `-SRSP`).

6. **Доставка в PWA:** та же схема, что уже используется в extension ↔ PWA: запись в `localStorage` ключа **`aristosPlatonusSync`** + `postMessage` с ack-подтверждением.
7. **В PWA:** отдельный стор/страница «Транскрипт / История», читающая этот payload.

### 9.2 Открытые вопросы интеграции

- ❓ Сколько лет доступно в селекте года журнала (глубина истории)?
- ❓ Поведение доп. периодов `-1` / `-2` — включать ли их в цикл загрузки?
- ❓ Восстановление сессии при истечении: как детектить (редирект на логин? код ответа?) и как переоткрыть `id.yu.edu.kz/platonus/oauth` из расширения.
- ❓ Формат авторизации v7 REST (`Bearer`?) — если понадобятся транскрипт/ИУП через API, а не журнал.

## 10. Чеклист «если что-то не работает»

| Симптом | Причина / действие |
|---|---|
| **Редирект на страницу логина** (`id.yu.edu.kz`) | Сессия истекла. Заново пройти вход: открыть `https://id.yu.edu.kz/platonus/oauth` → логин/пароль → повторно `/platonus/oauth` → редирект на `/v7/#/main-event/view`. После этого cookies обновлены. |
| **Пустой журнал** (HTML без предметов) | Неверный `studentID` или неверный `year`. Проверить `window.student.studentID` на странице журнала и корректность пары year/term (term: 1 = осень, 2 = весна). |
| **fetch без данных / 401-подобное поведение на `/rest/api/...`** | Возможно, не передан токен. Взять `localStorage.getItem('token')` на домене `platonus.yu.edu.kz` и добавить заголовок (предположительно `Authorization: Bearer <token>` — формат не подтверждён, проверить перехватом XHR). |
| **`studentID` не найден** | Не открывать журнал напрямую с придуманным ID — сначала загрузить `/student_register` без параметров и прочитать `window.student`. |
| **Не находятся таблицы оценок при парсинге** | Таблицы НЕ лежат в исходном HTML — они грузятся XHR-ом `getMarks` по клику на карточку в `#marksModal`. Расширение кликает каждую карточку (hidden-таб) и поллит модалку из воркера. Модалка фильтруется по обязательным меткам строк «Месяц»+«Дата»+«Оценка» (таблица посещаемости отсеивается). Свежесть контента проверяется сравнением `modal-title`/`textContent` с до-кликовым снимком. |
| **v7-страница (транскрипт/ИУП) пустая** | Данные ленивые: вкладка должна быть реально открыта в SPA, иначе XHR не уходит. Либо использовать журнал `/student_register` вместо транскрипта. |
| **Расхождение «Итог» с донутом** | Пересчитать формулу §5 на точных числах журнала (не округляя промежуточные РК/Рейтинг); итог округляется последним. |
